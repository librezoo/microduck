## 0. 一页结论

**目标。** 让 microduck 在唱一首歌时，嘴和头颈呈现可信、有表达意图的演唱动作：延音嘴形保持、密集歌词有清楚但不机械的开合、
头部按乐句而不是按拍子运动、整首歌看不出循环。

**推荐路线［决策］：** 规则 + 程序化动画为主干，建立在一个**独立的表演表示**（Performance：音节、乐句、段落、拍点，全部在歌曲时钟上）之上；
音频分析（人声分离、对齐、节拍、结构）是**离线**的、产出这个表示、带置信度、可人工修补；机载只运行编译好的动作并负责时钟、仲裁和安全。
学习式动作生成不放主线，放一个**有停止条件的并行实验**（§6）。

**最重要的五个架构判断：**

1. **表示先于算法。** 嘴和头的所有质量问题都可以归结为"输入里有什么"：只有响度就只能做出响度跟随；
   有元音、音高、乐句、段落才可能做出有结构的动作。所以系统的核心接口是 `Performance`，不是某个模型。（§5.1）
2. **机构是第一约束，不是最后一步的"适配"。** 一维的嘴在快歌词里**物理上画不出**每个音节的开合。
   生成器必须把"这个机构在这段时间内能做多深"算进设计里，快段退化成小幅颤动而不是破坏时序。（§5.2，已实现并有测量）
3. **头部延迟比一个点头还长。** 在 MuJoCo 孪生里实测头部从命令到关节有 **210–280 ms** 延迟，而重音点头的时间尺度是 70–120 ms。
   所以头部的"宣告类"动作（换气、乐句开头、段落情绪）必须提前编排并按实测延迟补偿，快层则要上真机验证是否还有可见效果。（§7.2）
4. **时钟与仲裁归机载运行时，创意归离线。** 动作编译可以在笔记本或机器人本身做（几十毫秒），但谁拥有嘴和头、
   seek/暂停时怎样不让关节突跳，是运行时的责任，且已经用测试固定下来。（§7）
5. **证据分层，不混用。** "代码对"、"信号达标"、"机构执行对"、"观看者觉得像在唱"是四层证据，上一层不能代替下一层。
   本轮已经做完前两层的一部分和第三层里**仿真能做的部分**；第三层的其余和第四层必须上真机、上观众。（§8）

**本轮已经做了什么**（§12 有命令和结果）：新 crate `singer`（表演表示、嘴/头生成器、播放器、机构模型、指标、基线）；
IPC 新增 `robot.sing`，`robotd` 接入控制环，`robotctl sing` 命令；33 个新测试；在真实的 `robotd` + MuJoCo + 平衡策略上跑了
三首歌共约 5 分钟的表演、停止、边走边唱，并用对照实验确认没有扰动平衡。

**本轮没有做、不能声称做了的：** 任何真机；真实歌曲的音频分析；任何观众评估；嘴的物理执行（MuJoCo 孪生**没有嘴关节**，见 §2）。

## 1. 目标、体验与范围

### 1.1 要达到的体验，翻译成能力

| 体验 | 能力（可研发） | 主要依据 | 验收（§8） |
|---|---|---|---|
| **开唱前的准备**：先吸一口气、抬头，再开口 | 乐句前的"换气 + 抬头"、第一个音前嘴微张的换气提示 | 头部情绪动作可早于发声数秒［原文：Livingstone & Palmer 2016］ | 乐句前 0.2–0.6 s 内头部抬升达标；换气提示出现在 ≥0.35 s 的静默里 |
| **歌词发音**：能看出"啊"和"呜"不同 | 元音→开口度；音高/响度加宽；高处窄元音被拉开 | 下颌开度随元音和音高变化［摘要：Sundberg & Skoog 1997］ | 开口度与元音预期相关；高潮音不比开头更窄 |
| **持续长音**：嘴形保持 | 保持段、起音后的轻微松弛、小幅慢漂移 | 歌唱中元音占主导［转引］ | 长音窗口内开度起伏 ≤ 设计目标，且不是冻住 |
| **一字多音**：一个字几个音，不闭嘴 | `Syllable.tie`：续音只跟音高、不开合 | 工程规则，需对齐歌词才知道 | 续音处无超过阈值的凹陷 |
| **连贯演唱 vs 快速歌词** | 按机构能力计算每个音节间最大可行行程；快段缩小幅度而不乱时序 | 工程规则 + 机构限制 | 速度、加速度不越限；"可行的开合"全部做到 |
| **换气与休止** | 休止闭嘴；长休止前换气提示；头部在换气时转移姿态 | 同上 | 休止内闭合比例；头部姿态在休止中切换 |
| **乐句起伏** | 乐句弧线（走向高潮的抬升、之后的缓落） | 工程假设 | 乐句内头部俯仰与乐句强度相关 |
| **重音强调** | 重音点头，带不应期、与拍点点头互相让位 | 工程假设 | 重音数、不应期、叠加后不超预算 |
| **高潮与收势** | 段落情绪提前抬头；末尾下沉 | 同上 | 段落前 2 s 起头部已变化 |
| **间奏中的听歌状态** | 无人声时保留一部分拍点点头 + 慢漂移 | 工程假设 | 无人声段运动不为零也不乱 |
| **整首歌连贯，不露循环** | 段落变体（重复副歌同族不同样）、相位连续的多周期漂移、确定性种子 | 工程假设 | 重复段相似度落在"同族不同样"区间；运动包络不比音乐自身更循环 |

### 1.2 范围

**核心：** 歌唱表演控制（嘴、头、颈，以及注视的接口）。**不自动纳入必做：** 歌声合成、完整舞蹈、通用情感智能。
现有的声音合成（`sounds`）是个可用的"唱歌"来源，但不是本项目的目标；真实歌曲的音频由别处播放。

**眼睛。** 仓库里**没有眼屏接口**［已确认：在代码和文档中检索 eye/display/screen/gaze，没有眼屏驱动；`robot.look` 是用头做注视的 IK］。
所以"眼神"在第一阶段只能靠头的朝向表达。眼屏作为扩展轨道 X3：本文预留了表演表示里的注视字段，不阻塞主线（§5.5）。

### 1.3 三个扩展能力的评估

| 能力 | 价值 | 难度 | 对系统的影响 | 建议 |
|---|---|---|---|---|
| **实时跟唱 / 流式** | 高（用户放任意歌即可） | 高：没有未来信息，乐句边界、重音、段落情绪都无法提前；头部延迟 ~0.2–0.3 s 使"宣告类"动作做不到 | 嘴可降级为"响度 + 在线音高/元音估计"；头部只能滞后跟随 | **作为扩展 X1，不进主线。** 先做"带 3–5 s 缓冲的准实时"：缓冲换来乐句前视，质量介于离线与纯流式之间。共享的模块：Player、仲裁、机构模型、指标 |
| **流式生成歌声** | 中 | 高 | 与嘴的耦合反而简单（生成器同时给出音素） | **不做。** 不是本项目的核心 |
| **用户现场输入** | 中（互动） | 中到高 | 唯一输入是麦克风；需要说话/歌唱判别和自声屏蔽 | 并入 X1，不单独规划 |

## 2. 现有项目审查：已确认事实、可复用能力、缺口

### 2.1 已确认事实（均来自当前仓库；没有凭印象设定硬件）

**控制与关节。**
- 15 个关节，Dynamixel ID `20–24 / 30–34 / 10–14`；头颈和嘴在第二组，安全测试夹具给出 `neck_pitch=30`、`head_yaw=32`
  （`duck-control/src/model.rs`、`docs/design/robotd-design.md` §2.5）。
- 控制环 50 Hz；每个 tick 用 `sync_write_goal_position` 一次写全部目标（`duck-control/src/bus.rs`）。
- 嘴行程 **−5°（闭）到 +30°（开）**，`mouth_target(open: 0..1)` 做线性映射并夹紧；嘴不属于任何策略，
  `robot.mouth` 是唯一驱动它的东西（`duck-ipc-proto`）。
- 头 4 自由度：`neck_pitch / head_pitch / head_yaw / head_roll`，限位 `(-90°,60°) / (±90°) / (±170°) / (±25°)`。
  头目标**经策略指令进入**（偏移量加在客户端设定的头目标之上），所以头部运动是被平衡策略"跟踪"的，不是直写关节。
- 现有的歌唱先例：`chorale`（多鸭合唱）和 theremin 已经在驱动嘴和头：嘴按元音取开度并 τ=0.09 s 低通，
  头用 `head_expression(beats, reach)` 的固定正弦（幅度 ≤0.15 rad，测试固定）。
- 注视 IK：`robot.look`（`kinematics::head`）。
- 音频：`sounds` 是一个可种子化的合成器，`robotd` 用 `aplay` 管道播放；实时合成接口 `Stream`、合唱声部渲染。
  **没有任意 PCM 播放接口，只有音效库 + 合成器**。
- 所有权：theremin 与 chorale 各自**拥有**嘴；嘴的客户端意图只在 `driving` 时生效（`robotd/src/main.rs`）。
- 同意机制：`[chorale] accept`，默认 `false`，"移动嘴和头"是它存在的理由。
- 仿真：`scripts/duck-sim` 起真的 `robotd`，换 MuJoCo 身体（`microduck_rl` 的 `duck-body`）；`--fake` 无身体。
- 构建：仓库要求 `rustc 1.99`（`rust-version`），本机默认 stable 是 1.96，需要 `RUSTUP_TOOLCHAIN=1.99.0`。

**这次测量得到的硬事实：**
- **MuJoCo 孪生没有嘴关节。**`body_server.py` 在协议里插入/丢弃 index 9，body 模型里嘴是个静止的网格。
  所以**嘴的物理执行在仿真里无法验证**；只能验证到"daemon 下发的目标"（有）和机构模型（本文自建，参数为假设）。
- **头部延迟：命令→关节 210–280 ms**，增益 ≈ 0.9–1.1（偏航/横滚）、俯仰相关性 0.8–0.88（快成分被滤掉）。
  这是孪生里"策略跟踪 + BAM 执行器模型"的结果，**不是真机数字**。
- 真实控制环在三次表演（约 5 分钟）中**零新增丢 tick**；表演期间**零新增安全夹紧警告**。
- 平衡不受影响：站立策略下躯干倾角 RMS 空闲 0.59°、边唱 0.59°/0.37°，p99 都是 1.12°；
  走路策略下对照（不唱）RMS 0.70° / 最大 2.97°，边走边唱 0.50° / 2.84°。

### 2.3 离线 vs 机载

| 任务 | 放哪 | 理由 | 交换的内容 |
|---|---|---|---|
| 人声分离、对齐、音高、节拍、结构 | **工作站离线** | 算力（Demucs CPU 约 1.5× 时长［转引：官方 README］）、模型体积 | → `Performance` JSON + 分析置信度 + 来源 |
| 人工修补 | 工作站 | 需要 UI | → `patch` 文件（§4.5） |
| 动作编译（`Performance` → 嘴/头轨迹） | **都可以**；默认机载 | 几十毫秒，纯 Rust，无依赖；机载编译免去存两份产物 | 输入 Performance + Style + Profile，输出内存轨迹 |
| 时钟、播放、仲裁、安全 | **机载** | 只有机载知道谁在动关节 | — |
| 风格选择 | 离线建议，机载可覆盖 | — | Style 名 + 种子 |

## 3. 歌唱行为模型：哪些规律可以迁移到机器人

### 3.1 人类观察（附来源，并区分证据类型）

**嘴与下颌。**
- 元音决定张口的主形状，音高在高音区接管：专业歌手唱上行两个八度音阶时，/a/ 类元音的下颌开度随音高增大，
  其他元音到较高音高才开始增大［摘要：Sundberg & Skoog 1997，*J. Voice* 11(3)，10 名歌手；我只读到摘要，没有个体差异数据］。
  女高音在高音区把第一共振峰调到基频附近［转引：Joliveau, Smith & Wolfe 2004；Henrich et al. 2011，22 名歌手］。
  → **工程含义：** 开度 = 元音基值 × 音高/响度修正，**再加"高音把窄元音拉开"**（`climax_open`）。已实现（§5.2）。
- 歌唱里元音时长占比高于说话，辅音更短。转引的比例互相不一致（3:1 与 5:1），**确切比值［待验证］**。
  → 保持段占主要时间；辅音闭合是短暂的凹陷，常低于舵机能分辨的时间。
- **哪些能从音频可靠估计，哪些不能：**
  - 可靠：何时有人声、音高、响度、粗略元音类（需要对齐的帮助）、静默/换气区间。
  - 需要歌词 + 对齐：音节边界、元音身份、一字多音（`tie`）。
  - 即使有输入仍歧义：辅音的发音部位（一维嘴不可表达）、说唱段里"该不该闭"、伴唱重叠时"跟哪个声部"。

**头与颈。**
- Livingstone & Palmer 2016（*Emotion* 16(3)，12 名歌手，Optotrak 250 Hz）［原文］：说与唱的头部轨迹相似；
  开心→头抬高/俯仰向上，悲伤→头低；**这些差异在发声前 3.2–3.7 s 就开始，发声后持续约 2.4 s**；
  **偏航和横滚没有显著的情绪效应**；基频对头动的解释力在歌里比在说话里更弱。
  → **工程含义：** 俯仰是情绪通道，偏航/横滚是"观众扫视 + 姿态"通道，不要把情绪全压到偏航横滚上；
  段落级的头部"情绪"要**提前**开始（`MOOD_LEAD`=2 s，工程选择，因为它要塞进段落边界之间）。
- Munhall 2004（*Psych. Sci.*，1 名说话者，12 名听者）［原文］：自然头动提高噪声中的可懂度，**加倍的头动不比没有更好**。
  → 幅度不求大，求在预算内可信；"夸张"不是免费的。
- 上升的音程伴随头的抬起和上仰［转引：Thompson & Russo 2007；Thompson, Russo & Livingstone 2010］。→ 乐句弧线里俯仰随音高相对位置。
- **随拍点头、乐句结构与头动的关系：没有找到歌手的一手测量［待验证］。** 本文的拍点点头层是动画经验，不是实验结论，
  所以它在风格里是个**参数**（民谣型弱、流行型强），并列入消融实验。
- 演奏者之间，头动是协调时序线索［摘要：Kawase 2014，钢琴二重奏］。对单只鸭的独唱不直接适用。
- 独唱者面向观众的注视：**没有可靠来源［待验证］**。

**个体差异。** 上述研究样本小，个体差异大；本文因此不把任何数字当作"人类定律"，所有幅度都是可调参数，且按"该特征的**方向**和**时间关系**"迁移，不迁移绝对值。

### 3.2 行为转译原则（对后续设计有直接约束）

| # | 原则 | 落到哪里 |
|---|---|---|
| T1 | **保留时序与方向，放弃幅度和维度。** 一维嘴只能表达"开多大、何时闭"，保留这两样 | 嘴只有开度一个通道；唇形/舌位不表达 |
| T2 | **嘴形要早于声音准备，且与机构延迟分开处理。** 艺术性的"提前张口"是风格参数（`anticipation`），机构延迟是标定值（`mouth_latency`），两者不混 | `MouthStyle.anticipation` vs `Profile.mouth_latency` |
| T3 | **可行性在设计时算，不在最后裁剪。** 先算这段时间机构能做多深的行程，再决定凹陷深度 | `mouth::transition` / `max_stroke`；`MouthStats.depth_limited` |
| T4 | **长音必须"保持"，但不能冻住。** 起音后小幅松弛，之后极慢漂移 | `Seg::Hold` |
| T5 | **头部按时间尺度分层，层间有优先级。** 乐句级（姿态/弧线）、秒级（换气）、拍级（点头）、百毫秒级（重音）、秒级（长音摇摆）、段落级（情绪） | §5.3 |
| T6 | **人类的多维嘴部表现，由头颈和（将来的）眼睛分担。** 开口不够表达的"强调"用头的重音点头补 | 重音层 |
| T7 | **直接复制人类动作 vs 生成适合机器人形态的动作：选后者。** 人类嘴部的自由度、速度和幅度都不是这副机构的；直接复制会在最快处失真。人类数据的用处是**监督信号和时间关系**，不是轨迹 | §6 的路线比较 |
| T8 | **风格 ≠ 幅度系数。** 风格改变"有哪些动作、什么时机"，角色（鸭）是不变量：点头多于横滚、视线朝前、嘴型干脆 | §5.4；`character_holds` 测试 |

## 4. 从歌曲到表演的信息链路

### 4.1 输入与质量等级

| 等级 | 输入 | 能得到什么 | 自动化 | 降级 |
|---|---|---|---|---|
| **L0** | 只有完整混音 | 人声活动、音高（RMVPE 能从混音估计）、节拍/小节、粗略结构、响度 | 全自动 | 嘴 = 响度 + 音高；无元音，无换气 |
| **L1** | + 歌词文本 | 对齐后得到字/音节时间；元音类、`tie` | 半自动（对齐 + 抽查） | 对齐失败的行退回 L0 |
| **L2** | + 分离的主唱轨（或用分离模型得到） | 更干净的对齐/音高/换气 | 自动 | 分离不可用 → L0/L1 在混音上做 |
| **L3** | + 音素级标注（人工或 SOFA 级对齐 + 校对） | 辅音闭合时刻 | 人工校对 | — |
| **L4** | + 乐谱/MIDI | 音符级音高、小节线；乐谱前端 `from_score` 已有 | 全自动 | — |

**当前已实现：** L4 的一条（乐谱 → `Performance`）和 `Performance` JSON 入口。L0–L3 是 S3 的工作。

### 4.2 分析能力、来源、成本、服务于哪个行为目标

只列有行为目标的特征；**许可证全部来自一手核查（2026-10-10）**，没核实的标 UNVERIFIED。

| 分析 | 候选 | 许可证／状态 | 服务目标 | 说明 |
|---|---|---|---|---|
| 人声分离 | Demucs（`adefossez/demucs` 维护分支） | 代码 MIT；**权重许可 UNVERIFIED**；原仓库已归档 | 干净的对齐/音高/换气 | CPU 约 1.5×时长［转引］。BS-RoFormer 实现 MIT，各检查点许可 UNVERIFIED。Open-Unmix 的 umxl 权重是 CC BY-NC-SA 4.0（非商用） |
| 人声活动、换气 | 基于对齐的静默 + 分离轨能量 | — | 乐句边界、换气 | 换气检测器（Nakano 等 2008，HMM，18 名歌手，召回 97.5%/精确 77.7%）只在**无伴奏歌声**上验证［摘要］ → 必须在分离后的人声轨上跑，混音上不可信 |
| 歌词对齐 | **SOFA**（MIT；歌唱专用，默认拼音字典，检查点许可 UNVERIFIED）；**MFA**（MIT，v3.4.3；中英模型 CC BY 4.0，但训练于说话） | 见左 | 音节/元音边界、`tie` | MFA 对歌唱的官方指导 UNVERIFIED；WhisperX（BSD-2）不是为歌唱设计的 |
| 音高 | **RMVPE**（Apache-2.0，可直接从混音估计）、**FCPE**（MIT）、**CREPE**（MIT） | 见左 | 开度的音高修正、乐句高潮、`tie` 的音高变化 | — |
| 节拍/小节 | **Beat This!**（代码和权重都是 MIT，ISMIR 2024，v1.1.0） | MIT | 拍点点头、重音的拍位 | 避开 madmom：**模型文件 CC BY-NC-SA 4.0**，非商用 |
| 结构 | All-In-One（MIT，需 NATTEN 和 madmom 的 git 版本 → 非商用风险可能传递） | 谨慎 | 段落（主歌/副歌）、变体计数 | 备选：自相似矩阵自己做 |
| 响度 | 简单 RMS/LUFS | — | 音节 `level` | 廉价 |

**不堆特征：** 颤音、滑音本身不单独建模——嘴的 0.1 以下小颤动机构做不出，头也不跟。它们只影响 `level` 和 `pitch` 的平滑度。

### 4.3 歌唱 vs 说话、语种、特殊情形

| 情形 | 处理 | 风险 |
|---|---|---|
| 说话 vs 唱 | 以对齐的音高稳定度判别：音高平台 ≥ 0.15 s 的算唱，否则当说唱/说话，使用 `chant` 风格 | 边界模糊 → 置信度降低 → 嘴幅度减小（已实现的低置信度规则） |
| 中文 | 韵母 a/o/e/i/u/ü → `Ah/Oh/Eh/Ee/Oo` 大致对应；声母 b/p/m/d/t → `Closure`，l/n/h/s → `Soft`/`None` | 声调导致的音高滑动不是旋律；对齐后需要把字级音高平滑 |
| 英文 | 音素 → 元音类 + 辅音类（ARPAbet 的表） | 双元音（/aɪ/）在单维嘴里只表达为起止两个开度 |
| 哼唱 / 无意义衬词 | `Mm` 或 `Ah`，`level` 低 | — |
| 说唱 | `chant` 风格：浅开合、重音多、少摇摆 | 对齐在说唱上比唱更好（接近说话） |
| 长音/颤音/滑音/一字多音 | 保持段 / 忽略 / 平滑音高 / `tie` | `tie` 需要对齐 + 歌词才知道；只有乐谱时无法判断 |
| 主唱与伴唱重叠 | 主线选择规则：优先 L2 分离后的最强人声轨；多声部歌曲机器人**跟最高声部（主旋律）**，除非用户指定 | 选错声部会让嘴跟着和声走 → 置信度下降、动作变保守；用户可以在 patch 里指定 |

### 4.4 置信度、失败处置、优先级

每个事件带 `confidence ∈ [0,1]`。**规则：** 置信度低 → 嘴开度向地板收缩（`0.7+0.3c`）；`< 0.4` 的音节不触发头部重音（已实现并测试）。
**优先级：人工修补 > 分析模型 > 规则推断**，从高到低覆盖，每次覆盖记录来源。
**整首失败：** 对齐失败率 > 阈值 → 整首退回 L0（响度 + 音高），并在日志和 `robot.sing` 的结果里**明说**降级，而不是静默变差。

### 4.5 人工修正入口

`Performance` 是**事件**，不是曲线，所以修一个音节边界只改那个事件再重新编译，不用重做整首歌。设计一个 `patch` 层：

```
base.performance.json   ← 分析产物（只读）
song.patch.json         ← 人工修正：[{op:"set", syllable: 41, start: 12.84}, {op:"merge_tie", syllable: 17},
                                      {op:"phrase_break", at: 38.2}, {op:"section", kind:"chorus", start:84.0, end:112.0}]
```
合成顺序：`base + patch → 校验 → 编译`。校验器（已有 `Performance::validate`）拒绝重叠、越界、非单调。每个补丁带作者和时间。

### 4.6 时间基准、偏移、可追溯

- **统一时间基准：歌曲时钟（秒，浮点），以音频文件解码后的第 0 个采样为 0。** 不同采样率重采样后用样本数/采样率换算；
  重新编码（MP3）引入的编码器延迟（约 1105 样本）和"静音头"在入口处用**音频指纹或互相关**对齐，偏移写入包元数据。
- **分轨偏移 / 剪辑版本：** 包里记录 `audio_sha256` 和 `offset_s`；播放前校验当前音频的哈希，不一致就拒绝或要求重新对齐（不静默播放错位的表演）。
- **可追溯：** `source`（`score:…` / `aligner:SOFA@<commit>`）、分析模型版本、补丁版本、`Style` 与 `seed`、`Profile` 都写进包的元数据；
  同一输入 + 同一版本 → 同一输出（确定性是设计要求，有测试）。

## 5. 表演生成层

### 5.1 表示：为什么是"事件 + 派生曲线"

**选择：** 以事件为真值（音节、乐句、段落、拍点），连续曲线是**派生**产物，不存储为真值。
理由：（a）局部修正只改一个事件；（b）同一份表示可以编译成不同硬件（换 `Profile`）和不同风格（换 `Style`）；
（c）评估可以直接按事件检查（"这个音节在 ±50 ms 内是否张开"）。
**不选的：** 纯曲线（无法局部编辑，换硬件要重做）；动作片段库（拼接处的连续性和长时一致性难，§6）。
**已实现：** `singer::Performance`（`singer/src/perf.rs`），带校验、JSON 往返、置信度、`tie`、`Onset`。

### 5.2 嘴（已实现，`singer/src/mouth.rs`）

**从发音到开度。** `open = clamp(元音基值 × 音高因子 × 响度因子 + 高音拉开项)`：
- 元音基值：与 `sounds::chorale::Vowel::open` 完全相同的数（"舞台元音"，保证看见的与听见的一致；已有注释说明为何不用语音学上诚实的值）。
- 音高因子 `1 − pitch_gain·(1−pn)`，`pn` 为该音在**这首歌的 5–95 分位范围内**的位置（"高"是相对这首歌的）。
- **高音拉开项** `(1−base)·climax_open·pn²·level`：来自"高音区所有元音开度都增大"。
  这条规则是**走查示例暴露出来的缺口**：加之前，一个高 ee 的最高潮音（0.41）比一个中音 ah 还窄。

**连续过渡与闭合。** 每个音节之间是"谷"：休止 ≥ 阈值 → 完全闭合；连音 → 凹陷，深度 = `legato_dip × 辅音因子`。
**可行性在设计里算：** 余弦缓动一次行程 Δ 需要时间 `max(π/2·Δ/v_max, π·√(Δ/2a_max))`；
可用时间内放不下就**二分求最浅可行的谷**；没有可行的就**不凹**（平滑接合）。阶梯：先保持到音末 −0.08 s，
不行再提前到 −0.2 s，只有**短音节（<0.3 s）**才允许整个周期都给行程。

**长音。** 起音后按 `settle` 松弛（时间常数 0.35 s），之后加极小的慢漂移（周期 1.9–2.9 s、相位由种子决定）。
**休止与换气。** 休止闭嘴；休止 ≥ 0.35 s 且有足够空间时，在开口前 ~0.4 s 张开 `breath_open`（0.06–0.14）表示吸气。
**非语言发声：** 哼 `Mm` 开度 0.05，不被修正项拉开。

**能量包络的能力上限（所以它只当基线和降级）：** 它不知道元音（开度只随响度）、不知道音高、不会在连音间凹陷（只会被动随响度下落）、
重新张口**晚于**声音。本轮在 6 个声部上测到：**起音准时**（口张到该音节自身峰值的 80% 之内，起音后 50 ms）设计 82/83，能量跟随 25/83；
民谣类 18/18 对 0/18。更高质量的版本靠**对齐给出的元音和 `tie`**突破这些限制。

**机构行为（测量）。** 开度到真实机构要经过延迟、滞后、死区、回差（`singer/src/mechanism.rs`，**参数为假设**）。
在"合理"和"悲观"两组参数下：
- **保持的长音：全部保留**（所有曲目 18/18、44/44…）；
- **起音准时：基本保留**；
- **快段连音的浅凹陷：大量消失**——例如 duck-strut 女高音 50/68 个设计出的连音凹陷在"合理"机构下变成 0/68
  （凹陷幅度在 1% 死区 + 1.5% 回差之内）。
- 这是**真实的设计信息**：在快歌词里，**嘴的开合已经不是区分音节的手段**。所以快段必须让头的重音和拍点承担"音节感"（T6），
  并且**标定死区/回差（S1）是最优先的测量**。

### 5.3 头颈（已实现，`singer/src/head.rs`）

九个层（`arc / pose / mood / idle` 是背景，其余是事件），**时间尺度和意图不同**，加起来要受预算和优先级约束：

| 层 | 尺度 | 内容 | 优先级 |
|---|---|---|---|
| prep | ~0.4 s | 乐句前吸气抬头 + 开口瞬间的小下点 | 最高 |
| accent | ~0.1 s | 重音快速下点（带 0.3 s 不应期） | 高 |
| beat | 1 拍 | 拍点点头；节奏快于 `nod_rate_max` 时只保留强拍 | 中 |
| sway | 2–3 s | 长音上的慢横滚/偏航，**相位全曲连续**不重置 | 低 |
| arc | 乐句 | 走向高潮的抬升、之后缓落 | 背景 |
| pose | 乐句 | 乐句内保持的朝向，**在换气时才转移**（扫视观众） | 背景 |
| mood | 段落 | 大段落头略高、安静段落略低，**提前 `MOOD_LEAD`=2 s 开始** | 背景 |
| idle | 4–8 s | 三个不可公度周期的极慢漂移，防冻住 | 背景 |
| bow | ~1.5 s | 结尾下沉 | — |

**冲突处理：** 高优先层压低低优先层（`g_beat = (1−0.8·acc)(1−0.8·prep)`），总和经 `budget·tanh(sum/budget)` **软限幅**（不削顶），
末级只做速度夹紧（透明于可行曲线）。**颈**取每次俯仰的 35%，不独自完成。

**重复不重样、确定性：** 所有变化来自 `hash(seed, 段, 重复序号)`，无逐帧随机；重复段第 `n` 次：
乐句抬升 +12%·n、第一次的弱拍点头 ×0.6、偏航方向镜像。**实测的缺口（§8 记录）：** duck-strut 的第 0 次与第 3 次副歌头部相似度 **0.90**，
太像复制（设计目标 ≤ 0.85）；原因是拍点点头占主导，需要在 S4 加入"点头选拍"的变体。

**符号：** 内部"俯仰向上为正"；到机器人的符号由 `Profile.head.pitch_up_sign` 转换，**默认 −1 沿用 chorale 的假设，真机未验证**。

### 5.4 整曲编排与风格

- **段落**驱动密度和幅度（`section.intensity`），重复段通过 `variant` 保持同族不同样。
- **提前 vs 滞后：** 准备类（换气抬头、段落情绪）**提前**，收势类（乐句末缓落、结尾下沉）**滞后**；
  设备延迟补偿（`head_latency`、`mouth_latency`、`audio_latency`）与此**分开处理**，在 `Show::sample` 里统一作用。
- **风格**（`style.rs`）三种，**结构不同而不是增益不同**：`ballad`（连音、少点头、长摇摆、大乐句弧线）、
  `pop`（拍点点头强、短摇摆）、`chant`（深开合、重音多、几乎无摇摆）。`Style::auto` 用速度和音节密度选，两个阈值，易覆盖。
  角色不变量（鸭：点头 ≥ 横滚、偏航小、嘴地板 ≥ 0.15）有测试固定。**风格差异的依据是动画工程假设，不是实验结论。**
- 幅度整体尺度 `Style::scaled` **只用于适配某只鸭**，不用于区分风格。预设已按 chorale 的可见幅度（roll 0.08 rad、lift 0.10 rad）放大 1.3 倍，
  仍是起点，等真机标定。

### 5.5 眼神与其他肢体
注视目前只能用头（偏航）。`Performance` 里预留注视意图的位置（S5 再定字段）；眨眼、眼神与头颈共享"表演意图"，
但**眼屏硬件接口不存在**，所以只写需求，不阻塞。其他肢体动作（轻微重心转移等）明确隔离在扩展轨道 X4，不与核心争资源。

## 6. 技术路线比较与决策

| 维度 | 规则 + 程序化（**主干**） | 动作片段检索/拼接 | 预训练音频驱动模型 | 学习式动作生成 | 混合 |
|---|---|---|---|---|---|
| 自然度上限 | 中，取决于规则质量 | 中—高（取决于库） | 对**人脸**高；对一维鸭嘴不适用 | 高（若数据够） | 中—高 |
| 可解释 / 可编辑 | **最高**（事件可改） | 中 | 低 | 低 | 中 |
| 长时一致性 | 高（全局规划） | 拼接处差 | 逐段，无整首视角 | 取决于架构 | 高 |
| 数据需求 | 无 | 需要动作库（自拍/动捕） | 不需要 | **大**（成对歌+鸭动作，不存在） | 小 |
| 机载算力 | 几十 ms，纯 Rust | 低 | 通常需要 GPU 或 NPU | 看模型 | 低 |
| 延迟 | 离线无关 | 低 | 流式可行 | — | — |
| 许可证风险 | 无 | 看库来源 | **见下** | 看数据 | 低 |
| 维护 | 低 | 中（库维护） | 中—高（外部模型版本） | 高 | 中 |
| 机构适配 | 直接（Profile） | 需重定向 | **重定向风险最大** | 需机构数据 | 直接 |

**预训练模型的真实情况（一手核查）：**
- NVIDIA Audio2Face-3D：SDK MIT，模型 NVIDIA Open Model 许可；输出下颌/舌/眼和 blendshape → 需要**从人脸表示重定向到一个一维嘴**，信息在重定向里丢掉的恰是它的强项。
- SingingHead（数据集 HF 上；**非商用研究协议**）：作者自己报告说话数据训练的模型在唱歌上变差；仓库的 3D 可视化脚本仍标"未发布"。
- VOCA：代码"免费用于非商用和科研"。FaceFormer：代码 MIT，数据（VOCASET、BIWI）许可 UNVERIFIED。
- Rhubarb Lip Sync：MIT；为说话设计的口型类（A–H、X），对歌唱的效果 UNVERIFIED。
- 最接近的机器人先例：AIST HRP-4C 的 VocaWatcher（人唱 → 嘴/眼/颈，用 VocaListener 的带时间歌词同步嘴［摘要］）；
  Ishi 等（ATR）用 F1/F2 元音空间旋转生成唇高/唇宽，加唇宽控制提高自然度［摘要］；
  Hu/Lipson 等（*Science Robotics* 2026）用 VAE + 面部动作 transformer 从音频驱动 10 自由度软唇，**演示了唱歌**［摘要］。
  这三条都说明：**有了对齐的元音/音素，规则式口型生成已是业内起点；学习式在多自由度嘴上更有收益。**

**决策［决策］：**
1. **主线：规则 + 程序化**，建立在 `Performance` 上。理由：一维嘴不存在人脸模型的优势；需要可编辑；无数据；无算力要求；许可证干净。
2. **嘴的"元音/音素"来自对齐（SOFA 或 MFA），不来自端到端模型。** 理由：这是 HRP-4C、ATR 的共同做法，且产出是事件，可人工修。
3. **头颈 = 规则主体 + 一个可选的学习式"偏好层"实验**（S8），只在规则层达标后才有意义；它的作用是**给规则层的参数选值**（逐段风格参数），不是替代。
4. **必须通过实验验证的关键决策：**
   - 一维嘴的"凹陷"能被观众看见吗（S1 标定 + S10 观看）；
   - 头的快成分上真机还有没有效果（S1）；
   - 拍点点头是否真的提高"在唱"的可信度，还是只增加机械感（S10 消融）。
5. **学习式的触发条件（S8 开始的条件）：** S10 的观看评估在"表演可信度"项上，规则版与一个**手工精修的上限版**之间差距 ≥ 设定阈值（见 §9），才投入数据与训练。
   **停止条件：** 数据收集 4 周后可用成对片段 < 200 段，或第一个重定向基线在 held-out 歌上不能超过规则版 → 停止，保留规则版，成果（数据、标注工具）保留。

## 7. 机载运行、同步、控制与安全

### 7.1 时钟与延迟

**统一主时钟：歌曲时钟。** `robotd` 控制环的单调时钟为底；播放开始时记录"请求时刻 = 歌曲时刻 −预卷（1.5 s）"。
**延迟的三类来源与处理：**

| 延迟 | 性质 | 本轮 | 处理 |
|---|---|---|---|
| 音频：从发出播放到声音到达房间 | 取决于声卡缓冲，**需测量**（回环麦克风） | 未测，默认 0 | `audio_latency`；所有动作按它相对偏移 |
| 嘴：命令→物理开合 | **需测量**（高速相机） | 孪生无嘴；默认 0 | `mouth_latency`；`Show::sample` 里**提前取样** |
| 头：命令→物理 | 孪生实测 **210–280 ms**；真机待测 | 默认 0，请求可覆盖 | `head_latency` 同上 |
| 控制环抖动（20 ms 量化） | 已知 | — | 轨迹按 50 Hz 离散，插值取样 |

**孪生里验证了补偿机制：** 头设定 `head_latency=220 ms` 后，测得关节相对**名义歌曲时间线**的滞后
从 +210/+210/+280 ms（俯仰/偏航/横滚）降到 **−10/−10/+60 ms**。（"名义时间线"是命令时间线减去所设提前量，这个验证说明补偿作用线性、可预测；
它不证明真机上的数字。）

**艺术性提前 vs 设备补偿分开：** 前者在风格里（`anticipation`、`MOOD_LEAD`），后者在 Profile 里。

**同步目标（设计目标，不是人体感知定律）：** 嘴起音相对声音：**嘴领先 0–60 ms**。依据：ITU-R BT.1359-1 把可检测阈约定为声音领先 45 ms ～ 声音滞后 125 ms
（即**画面领先容忍度大于画面滞后**）［原文，电视材料；Dixon & Spitz 1980 在语音上给出相近的不对称，转引］。
**电视数据对机器人鸭不一定成立，所以 S10 要自己扫偏移（−150～+250 ms）测容忍度。**

### 7.2 控制与平衡的所有权仲裁

```
                       theremin  chorale  sing   robot.mouth   robot.head
  嘴 (MOUTH_INDEX)      拥有      拥有     拥有    仅在 driving    —
  头偏移                 —       叠加     叠加     叠加到客户端头目标
```
**规则（已实现）：** theremin 和 chorale **拥有**嘴，solo 表演**拒绝在它们之下启动**，并在它们启动时**让出**；
嘴的客户端意图被表演覆盖（仅在表演期间）。头偏移是叠加量，客户端的头目标仍然生效。

**不同身体状态下的允许范围（暂定［假设］，需 S9 验证）：**

| 状态 | 嘴 | 头 | 说明 |
|---|---|---|---|
| 站立（stand 策略） | 全 | 全（预算内） | 孪生里测过：平衡无影响 |
| 走路（walk 策略） | 全 | 全 | 孪生里测过：倾角不变坏 |
| 坐（sitstand） | 全 | **缩小到 50% 预算** | 未测 |
| 跌倒 / limp | 关 | 关 | 摔倒时表演不应继续 |
| 抬起（pickup） | 关 | 关 | 同上 |
| 技能执行（roulade 等） | 关 | 关 | 技能拥有身体 |

当前实现里嘴只在 `snapshot.enabled && Ready` 时写入；**跌倒/抬起/技能时的自动暂停还没做**（S6）。

### 7.3 播放状态：暂停、恢复、跳转、切歌、结束、失败、急停

**已实现：** `Player` 输出 `show(t) + e`，`e` 是"关节现在在哪"与"表演说它该在哪"的差，以受限速率衰减。
稳态 `e=0`，输出就是设计曲线（没有跟踪滤波的滞后）；seek / 恢复 / 从静止启动后输出连续。
暂停/停止/结束：输出向**休止姿态**（嘴闭、头偏移零）以关节限制滑行，到达后报告 `Idle`。
速度上限：设计曲线 ≤ 85% 限制，`e` 的衰减 ≤ 15%，**合起来 ≤ 100%**（测试固定）。

| 场景 | 行为 | 状态 |
|---|---|---|
| 跳转 | `e` 吸收跳变；速度不越限 | 单测 ✔ |
| 暂停 → 恢复 | 先去休止姿态，恢复时吸收差值 | 单测 ✔ |
| 正常结束 | 滑行到休止，`robot.state.sing` 消失 | 单测 ✔，孪生 ✔ |
| 请求停止 | 同上 | 孪生 ✔（settling 状态出现） |
| 切歌（`robot.sing` 再次 start） | 新 `Performer` 替换旧的；旧的音频先 `sing_stop` | 孪生里只测了启停，未单独测切歌 |
| 播放失败（对齐包校验失败、哈希不符） | **在 `robot.sing` 入口拒绝并给出原因**，机器人不开始 | 已有入口校验；哈希校验是 S6 |
| 紧急停止 | 不靠表演层：`robot.stop/relax` 和 `Safety` 优先；表演层不得延迟它们 | 现有机制，未改 |

### 7.4 机构、安全与"设计曲线经过真实机构会怎样"

- 嘴行程是 −5°～+30°，**35° 对应 4096 刻度编码器约 400 刻度**，分辨率不是问题；问题是**死区、回差、速度、加速度、舵机内部轨迹规划、线缆和连杆干涉**。
- **本项目对 Dynamixel 的使用：** 每 tick 同步写 goal position，位置 P 增益有缓存写入，Return Delay 被固定为低值（`bus.rs`）。
  **仓库里没找到对 Profile Velocity/Acceleration 的写入［已确认：未检索到］，所以舵机用 EEPROM 里的 profile 设置，值［待验证］。**
  XL330 的手册（ROBOTIS e-manual）说 Profile Velocity 默认 0 = 无限速度（阶跃）、可选时间型 profile（Drive Mode bit2）、
  新目标会中途重新规划轨迹［原文］。这对本设计意味着：**我们 50 Hz 下发的细粒度轨迹会被舵机内部 profile 二次整形**——
  若 profile 太慢会削平快段；若是 0（阶跃），则由 P 增益决定响应。这是 S1 必须测的第一件事。
- **"设计曲线 → 真实开口"的修正方式：** S1 测阶跃/正弦响应得到 `{delay, tau, vmax, deadband, backlash}`，写进 `Profile`；
  设计阶段用这些数确定可行行程（已按 profile 做）；对残余的偏差用**前馈**（预补偿死区，把闭合目标放到 −ε 以保证闭紧）。
  **不用反馈**：嘴的位置反馈来自编码器读数，是否能代表"嘴实际开度"取决于连杆，先不依赖。
- **闭嘴的残余开度：** 机构模型里悲观参数下闭合后残留 3–4% 开度（死区 + 回差），这是**需要真机确认并用闭合预压解决的**问题。

**实机启用的前提、顺序、安全门槛（不凭空给安全角度）：**

1. **S9-0 台架无电：** 只验证软件路径、状态、停止。
2. **S9-1 嘴单独、卸载（头固定或拆下 ToF 之前）：** 只跑 `mute` 的嘴，限幅预算为 0；测延迟、死区、回差。
3. **S9-2 头偏移、坐姿、预算 25%：** 观察温升、电流（`currents_ma`）、噪声、线缆；预算每级翻倍的前提是**该级电流和温升不超过空闲基线的某个比例**（比例在 S9-1 的数据里定）。
4. **S9-3 站立**，同样阶梯。
5. **S9-4 走路 + 表演。**
6. **S9-5 整首、4 小时 soak。**
每一级的**门槛**是实测的（电流、温度、丢 tick、安全夹紧次数、平衡指标 vs 对照），不是预先给定的角度。**符号验证（俯仰向上是正还是负）是 S9-2 的第一步。**

### 7.5 实时/流式模式（扩展 X1）
缓冲 3–5 s 换乐句前视；增量分析（在线音高、VAD、节拍）产出**可修订**的事件，已提交给 Player 的部分不撤回，只能被后续事件**平滑覆盖**。
端到端延迟预算（暂定）：采集 100 ms + 分析 300 ms + 缓冲 3000 ms + 补偿 220 ms。与离线共享：`Performance`、生成器、Player、仲裁、指标；
**必须接受的质量限制：** 没有乐句前视 → 头部"宣告类"动作不可用；段落情绪不可用；嘴降级为音高 + 响度。

### 8.4 观看评估（小团队可执行）

- 方法：ITU-T P.910 §8.4 配对比较，Bradley–Terry 打分；MUSHRA 是音频方法，需改造，不直接用［转引：官方文件目录］。
- 条件（消融）：A 嘴仅随响度（基线）· B 嘴加元音/凹陷 · C 头仅拍点 · D 头加乐句编排 · E 完整多部位 · F 手工精修上限版（做对照）。

- 规模：≥ 15 名观众 × 8–10 段 × 5 条件；至少 3 首是**留出歌曲**；每人看 2 段完整歌曲。

### 9.1 各阶段

**S0 基线与证据底座** ［本轮完成］
- 目标：表示、生成器、播放器、基线、指标、仿真验证。
- 工作包：`singer` crate；`robot.sing`；`robotctl sing`；孪生测量；本文档。
- 交付：§12 清单。
- 验证：33 个新测试 + 孪生记录。
- 退出：✔。
- 风险：孪生没有嘴；头的数字不是真机。

**S1 硬件事实与标定台**（~2–3 人周；需要 1 台机器人 + 240 fps 相机）
- 前置：S0。无需 S3。
- 工作包：
  1. **嘴**：阶跃与 0.5–8 Hz 扫频正弦；测 delay/tau/vmax/deadband/backlash/闭合残余；比较"有负载"（贴合嘴壳）与"空载"。
  2. **头**：阶跃与正弦；增益、延迟、各关节的最大安全偏移（逐级放大，看电流/温度）；**符号验证**；
     快成分（≤0.1 s 点头）是否还能被看见。
  3. **舵机 profile**：读取并记录 Profile Velocity/Acceleration 和 Drive Mode；试时间型 profile 对嘴的收益。

**S2 高质量嘴**（~3–4 人周）
- 前置：S1 的 Profile（可先用假设值开发，S1 出来后重调）。
- 工作包：音素/元音类映射表（中英）；`Onset` 从辅音类推；`tie`（一字多音）；对齐置信度进入开度；说唱型"深开合"；
  消融（嘴仅响度 vs 嘴加元音 vs 加凹陷 vs 加 `tie`）。
- 交付：`singer::phoneme`（映射表）、一套嘴的消融样片。
- 验证：指标 + 小规模配对比较（嘴类 A vs B，6 人）。
- 退出：起音准时 ≥ 95%，元音相关性 ≥ 0.8（对齐输入下），`tie` 无凹陷；配对比较 B 胜 A ≥ 70%。
- 停止/备选：若 B 与 A 在观看上无差异 → 嘴的元音信息价值低，降级为 A + 起音准时，把预算转给头。

**S3 音频分析流水线**（~5–7 人周）
- 前置：无（可与 S1 并行）。
- 工作包：`singer-prep` 离线工具（工作站）：分离（Demucs/BS-RoFormer，需先确认**权重许可**）→ 对齐（SOFA 或 MFA；先在 10 首中/英歌曲上比较）→
  音高（RMVPE/FCPE）→ 节拍/小节（Beat This!）→ 结构（自相似或 All-In-One）→ 换气（人声轨上）→ `Performance` + 置信度 + 溯源。
  时间基准、哈希、偏移校验；`patch` 合成。
- 交付：命令行 `singer-prep song.wav --lyrics l.txt` → `song.performance.json` + 报告。
- 验证：与人工标注的 20 首（每首取 30 s）比对：音节起点误差中位数、F1（±100 ms）、段落边界误差；分离/对齐失败的比例。
- 退出：音节起点中位误差 ≤ 60 ms（目标，依 S1 给定的嘴时间分辨力调整）；失败整首可降级且**明说**。
- 风险：歌唱对齐在伴奏重的歌上变差；中文声调；许可证（权重）。**停止条件：** 若对齐质量在留出歌上不达标，走 L0 路线（响度 + 音高，无元音）作为产品默认，把对齐留为"可选的高质量"。

**S4 头颈与整曲编排**（~3–4 人周）
- 前置：S2 的事件质量；S1 的头延迟与可见性。
- 工作包：**重复变体**（点头选拍、乐句抬升、偏航镜像、摇摆相位）把重复相似度拉进 0.3–0.85；
  **句内静止修补**（长音型乐句的次级运动）；`pose` 扫视考虑段落变化；`mood` 提前量按 S1 的头延迟重定；
  **快层可见性**：若 S1 显示 <0.1 s 的点头真机不可见，把重音改为"提前一点的小幅 + 嘴的强调"；
  "整首连贯"：段落 intensity 序列平滑。
- 交付：新的 `head.rs` 层 + 测试 + 4 首完整歌的 CSV/视频。
- 验证：§8.2 的头部指标 + 配对比较（C vs D vs E）。
- 退出：重复相似度全部落区间、静止 < 1.5 s、循环度 ≤ 音乐 + 0.15；D 胜 C ≥ 70%。

**S5 多部位协调**（~2–3 人周；若有眼屏 +2）
- 前置：S4。
- 工作包：嘴、头、颈的耦合（颈分担俯仰比例标定）；`robot.look` 做段落开头/结尾的朝向（观众/摄像头）；
  眼屏接口调研与需求（硬件不存在则只写接口）；眨眼时机与乐句边界对齐。
- 退出：E 胜 D；颈/头比例有标定；眼接口需求书。
- 备选：无眼屏 → 注视完全由偏航承担。

**S6 机载产品化**（~3–4 人周）
- 前置：S1、S3 的包格式。
- 工作包：**歌曲包格式**（`.duckshow/`：`audio`、`performance.json`、`patch.json`、`meta.json`：哈希、偏移、版本、Style、seed、Profile 引用）；
  `[sing]` 参数节（延迟、预算比例、符号、风格默认）；`robot.sing` 增加 `package` 入参；音频播放集成（用歌曲音频而不只合成器；需要**新的音频路径**）；
  跌倒/抬起/技能时自动让出；pause/resume/seek 的 IPC；切歌；`robot.state.sing` 增加预算使用率；BLE 路由评估；诊断日志。
- 退出：4 小时 soak 无 tick 丢失；所有状态切换有测试；包校验失败入口拒绝。

**S7 编辑与诊断工具**（~3–4 人周，并行）
- 工作包：控制台里的时间线视图（音节/乐句/段落/曲线）；点击修补；`robotctl sing --explain`（说明某时刻为何这样动：哪层贡献多少）；
  CSV/视频导出；与 `sing_report` 对接的回归面板。
- 退出：能在 5 分钟内改一个音节边界并看到效果。

**S8 学习式实验**（~6–10 人周，**并行、有门槛**）
- 触发：S10 初评中"演唱可信度"规则版与精修上限版差距大。
- 工作包：自拍/动捕演唱数据 → 成对片段；监督目标 = **规则层的参数**（逐乐句风格选择）而不是原始轨迹；小模型；重定向基线对比；留出歌验证。
- 停止条件：见 §6。成果（数据、标注工具）保留。

**S9 实机分级启用**（~2–3 人周 + 墙钟时间）：见 §7.4 的阶梯和门槛。
- 退出：S9-5 的 4 小时 soak 无硬件报警、温升在门槛内、平衡指标不劣于对照。

**S10 感知评估与最终验收**（~3–4 人周）：见 §8.4 和 §10 的验收问题。

**扩展轨道（不在主线退出条件内）：** X1 准实时/流式；X2 现场输入；X3 眼屏；X4 其他肢体。

### 10.4 这个例子暴露了什么（已处理 / 待处理）

| # | 暴露的问题 | 状态 |
|---|---|---|
| 1 | **高潮音在窄元音上，嘴反而比开头窄**（第一版是 0.41，低于"好"的 0.69） | **已修**：加 `climax_open` 高音拉开项（现 0.66–0.70）+ 测试 |
| 2 | **一字多音会被当成三个音节而闭嘴** | **已修**：加 `Syllable.tie`；但**只有对齐歌词才能知道**，纯乐谱前端无法判断（仍为 `false`） |
| 3 | 休止期"嘴闭不严"（悲观舵机残留 3–4%） | 待 S1：测量并用闭合预压解决 |
| 4 | 头在 7.4–9.3 s 的 1.9 s 休止里，偏航停在 +0.06～0.07 rad：休止期缺乏"听/呼吸"运动 | 待 S4：休止期的次级运动 |
| 5 | 这是第一句，**第一句开头 2.2 s 抬头 +0.025 而 2.5 s 下点 −0.035，两者间隔 0.3 s**：孪生测得头延迟 0.21–0.28 s，这个"抬头→下点"在真机上会被低通成一个起伏，看不出两个动作 | 待 S1/S4：按 `head_latency` 把 prep 提前量加大，或合并成一个动作 |
| 6 | 重音"好"在头上的下点（<0.1 s）被头部延迟滤掉的风险 | 待 S1 真机；见 §2.1 孪生记录 |
| 7 | 示例里"换气"是休止内部一个 ~0.08 的嘴提示 + 头抬起 +0.071；**嘴提示在悲观舵机里 0.08 与残留 0.04 难以区分** | 待 S1：若不可见，换气只由头表达 |

### 11.2 需要向你确认的信息（集中列出）

1. 嘴舵机的型号、固件，以及 EEPROM 中 Profile Velocity/Acceleration、Drive Mode 的当前值。
2. 嘴的机械：是否有回弹/限位块；嘴壳是否在行程两端有接触；有没有可更换的连杆。
3. 歌曲音频**由谁播放**？是机器人的扬声器（需要新增任意 PCM 播放路径）、还是外部设备？这决定 `audio_latency` 的测法与 S6 的范围。
4. 是否要支持商业分发？这决定分离/对齐模型的权重许可是否是硬约束（§4.2）。
5. 是否有眼屏/眼部硬件的规划？没有则 X3 保持不动。
6. 测试集的歌曲授权来源。
7. 可用于 S1 的高速相机和能否拆下 ToF（S9-1 的头卸载测试）。

### 12.4 局限（不要把它们当成通过）

- **嘴在仿真里没有物理执行。**表中嘴的"悲观舵机"来自 `mechanism.rs`，参数是假设。
- **头的数字是孪生的，不是机器人的。**
- **音频路径未验证：** macOS 无 `aplay`，非 `--mute` 的发声路径只走到 `sing_start` 失败后安全返回；真实发声未在本机验证。
- **seek / 暂停没有 IPC 入口**（只有 start/stop），它们只在 `Player` 单测里验证。
- `mediad` 有一个与本改动无关的测试失败（`turn::tests::a_failure_names_its_cause_and_not_just_itself`，需要 TLS 到 `turn.invalid`，沙箱网络导致）；其余受影响的包全部通过。
- 重复段相似度 0.90、outer-wilds 女高音句内静止 1.6 s、休止闭合 0.82/0.85 **低于设计目标**，已列入 S2/S4。
- 没有任何观众评估。

## 13. 最终验收应当能回答的问题

1. **怎么加一首新歌？** `singer-prep song.wav --lyrics l.txt` → `.duckshow/`，`robotctl sing --package`；歌词缺失时降级到 L0 并明说。
2. **怎么得到可用表演？** 自动流水线的产物带置信度；报告列出哪些行/段是低置信度；默认风格由速度和密度选。
3. **什么时候需要人工修正？** 报告里的低置信度条目；对齐失败的行；段落划分不对；换气位置不对。用 `patch` 改一个事件，不用重做整首。
4. **怎样安全播放？** 同意开关 + 状态门（站/走/坐、非跌倒、非抬起、技能时让出）+ 预算 + 速度限制 + 休止姿态；实机按 S9 阶梯。
5. **怎么判断质量真的达标？** 四层证据都有：测试、指标、孪生/真机执行、留出歌的配对比较与偏移扫描；加手工精修上限版做天花板。
